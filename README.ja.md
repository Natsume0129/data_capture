# シナリオ表情データ収集

動画アノテーション：プロジェクト内で `./run_annotation.ps1` を実行するとローカルブラウザーが開きます。API は不要です。フォルダーを選び「打开」を押すと、その直下の動画だけをファイル名順に表示します。動画ごとに一区間と neutral / polite smile / bitter smile の一分類を選びます。Space：再生／停止、矢印：±0.1秒、I/O：開始／終了、1/2/3：分類、Enter：保存して次へ、P：前へ、L：ループ、D：除外。入力欄にフォーカスがある間はショートカットが無効です。

元動画は保持し、同じフォルダーに `元ファイル名_trimmed.mp4` と `annotations.csv`（出力ファイル名・出力先フォルダー・分類）を保存します。`.video_annotations.json` は再開用です。D は元動画を削除しませんが、その項目の生成済み動画と CSV 行を除去します。最初の表示ではローカル一時プレビューを作成します。出力完了とエラーの解消を確認してからターミナルで Ctrl+C を押してください。同じフォルダーへの同時起動や処理中の Excel による CSV オープンは避けてください。FFmpeg を指定する場合は `./run_annotation.ps1 -FFmpeg "C:\ffmpeg\bin\ffmpeg.exe"` を使用します。

## プロジェクトの使い方

55場面の統合版は `question_set/combined_all_smile_scenarios_55_ja.json`（一覧名：**苦笑い・表情会話シナリオ統合版（55場面）**）と `question_set/combined_all_smile_scenarios_55_zh.json`（一覧名：**苦笑与社交表情情景题库·中文整合版（55个场景）**）として引き続き利用できます。
既定の問題セット一覧には、統合版とラウンド別のセットが表示されます。日本語のラウンド別ファイルは `question_set/smile_scenarios_round_01_ja.json` ～ `question_set/smile_scenarios_round_05_ja.json`、中国語は `question_set/smile_scenarios_round_01_zh.json` ～ `question_set/smile_scenarios_round_05_zh.json` です。各言語の第1～5ラウンドはそれぞれ11場面で、ラウンド間の重複はなく、5ラウンドで55場面すべてをカバーします。
実験ごとに一つの言語だけを選択してください。日本語セットのTTSは `ja-JP`、中国語セットは `cmn-CN` を使用します。両言語のセットは画像を共用します。
場面の説明を表示・再生した後、スペースキーで録画を開始し、画像と最初の台詞を表示・再生します。その後もスペースキーで台詞を順番に進め、最後に終了します。

### 必要な環境

- Windows 10 または 11
- Python 3.13
- FFmpeg：`PATH` に追加するか、アプリ内で実行ファイルを選択
- DirectShow対応カメラ

### インストール

PowerShellを開き、次を実行します。

```powershell
Set-Location "D:\datacapture"
py -3.13 -m venv .venv313
.\.venv313\Scripts\python.exe -m pip install --upgrade pip
.\.venv313\Scripts\python.exe -m pip install -r requirements.txt
```

仮想環境がすでにある場合は、最後の2つのコマンドだけを実行して更新します。

録画にはPyAV（`av>=16.1,<17`）が必要になりました。既存の環境では `.\.venv313\Scripts\python.exe -m pip install -r requirements.txt` で依存関係を更新し、アプリを閉じて `.\run.ps1` から再起動してください。

### 起動

```powershell
Set-Location "D:\datacapture"
.\run.ps1
```

PowerShellがローカルスクリプトをブロックする場合：

```powershell
powershell.exe -ExecutionPolicy Bypass -File "D:\datacapture\run.ps1"
```

現在はソースから起動してください。パッケージ化された実行ファイルは、まだ正式な起動方法ではありません。

### 実験の実行

1. 匿名の被験者IDを入力します。
2. 保存先、乱数シード、動画分割方法を選択します。必要に応じて **場面間の休憩（秒）** を設定します。既定は10秒で、4～300秒の範囲で設定できます。
3. `question_set` から日本語または中国語の問題セットを選択します。既定ではすべて未選択です。ラウンド別に収集する場合は、使用する言語と第1～5ラウンドのうち該当する一つだけにチェックを入れ、統合版や他のラウンドを同時に選択しないでください。目標クリップ数はセットの選択や練習設定の変更に合わせて自動更新されます。練習が無効の場合は選択した全セットの `segment_count` の合計、有効の場合はその合計から1を引いた値（最小0）です。セットが未選択の場合は0で、neutral クリップは目標に含まれません。
4. カメラを選択し、プレビューで構図と解像度を確認します。
5. 音声を使う場合は、下記の手順でGoogle Cloud TTSを有効にします。
6. **開始前に練習場面を実施** の設定を確認して実験を開始します。既定ではチェックが入っており、アプリはこの設定を記憶します。有効な場合、最初に抽出された場面全体が練習用となり、正式な `manifest.csv` には含まれません。チェックを外すと正式な場面概要に直接進み、選択したセット内のすべての場面を正式収集に使用できます。
7. 場面の概要を確認します。この段階ではカメラは開いていますが、録画は始まっていません。
8. スペースキーを押して場面を開始します。アプリは場面全体を一本の元動画として連続録画し、同じ場面では常に同じ画像を表示します。
9. 場面内の台詞を順番に実行します。各台詞は場面の画像と一緒に表示・再生されます。自然に反応し、表情が自然な状態に戻ったら、スペースキーで次へ進むか終了します。
10. 最後の項目が終わると場面の録画を停止します。FFmpegが時刻に基づいて正式クリップを作成します。
11. 次の正式場面がある場合、neutral の休憩を自動で録画します。カメラに正面を向け、十字を見ながら顔の力を抜いてください。休憩中は画像・台詞・音声を提示せず、スペースキーでスキップすることはできません。休憩が終わると次の正式場面の概要に自動で進みます。休憩は正式場面と正式場面の間だけに入り、最初の正式場面の前、最後の正式場面の後、練習から正式収集への切り替えには入りません。したがって、一つのラウンドで11場面すべてを正式収集した場合、neutral の録画は10本になります。

選択した保存先には、場面と休憩の元動画、分割クリップ、`manifest.csv`、`stimuli.json`、`session.json`、時刻ログが作成されます。練習を有効にした場合は練習動画も作成されます。動画にマイク音声は入りません。ファイルは現在のユーザー権限で作成され、管理者権限なしで削除できます。

新しい録画はPyAVで可変フレームレート（VFR）のMP4に保存し、実際に取得した各フレームの単調時計のタイムスタンプを使用します。最後のパケットの継続時間は、実際の録画停止時刻まで延ばします。これにより、公称フレームレートで保存していたために生じる時間の圧縮を修正します。例えば、実際の10秒間で取得した50フレームを従来の方法で30 FPSとして保存すると、約1.667秒になる場合がありました。重複フレームや黒いフレームは追加しません。カメラの列挙と取得には引き続きOpenCVを使用するため、入力の実フレームレートが低いままの場合があり、カメラの黒い画面は今回の修正対象ではありません。録画が実際に空、または2秒を超えて実フレームを受信できない場合は、エラーで停止します。Neutral の先頭3秒を除く規則は変更しません。修正は新しい録画のみに適用され、過去の動画はフレームごとの時刻履歴がないため、元の時間軸を確実には復元できません。

カメラ名に `C920` が含まれる場合（大文字・小文字を区別しない）のみ、MJPEG（`MJPG`）入力、1920×1080、30 FPSを優先して要求します。その他のカメラは既存の取得設定を維持します。ドライバーが要求を拒否した場合、またはMJPGの最初のフレームを読み取れない場合は、既定の形式に戻して理由を記録します。これらは要求値であり、実際の30 FPSを保証するものではありません。MJPEG入力でもMP4/H.264 VFR出力は変わらず、依存関係も追加しません。

プレビュー時と実験開始時の取得診断は、プロジェクトの `logs/camera_capture.jsonl`（Gitの管理対象外）に記録します。実験の診断は `session.json` の `camera_capture` と、`logs/events.jsonl` の `camera_capture_config` イベントにも保存します。要求設定、ドライバーの応答、最初の実フレームのサイズ、`measured_capture_fps` を含みます。後者はカメラの読み取りと処理経路を通じて実際に受信したフレームレートであり、ドライバーの `reported_fps` とは異なります。被験者向けの実験画面は変更せず、カメラの状態表示も追加しません。更新後のプレビューを確認する前に、実行中のアプリを閉じて `.\run.ps1` から再起動してください。開発機では実機カメラによる検証を行っていません。収集用ノートPCでC920を選択し、プレビューと診断を確認してから正式収集を開始してください。

Neutral クリップでは、休憩の録画から先頭3,000ミリ秒を除きます。通常の10秒の録画からは約7秒の neutral 動画が得られます。`raw` には休憩の録画全体が残ります。Neutral 動画は他の分割動画と同じ `clips` に保存され、`manifest.csv` の `stimulus_format='neutral'` と `purpose='neutral'` で識別できます。events ログには休憩の開始・終了と trim 情報を記録します。Neutral 動画にも既存のサイレント分割または実験終了後の分割設定を適用します。カメラによる実際の休憩録画が3秒以下の場合、トリミング後に有効な neutral 動画が残らないため、アプリはエラーを表示して停止し、空の neutral クリップは作成しません。

5ラウンドで55場面すべてを正式収集する場合は、毎回 **開始前に練習場面を実施** のチェックを外すことを推奨します。練習を有効にしたラウンドでは11場面のうち1場面を練習に使用するため、正式収集は最大10場面です。目標クリップ数は場面数ではなくクリップ／台詞の数で、自動計算されるため手動設定は不要です。練習が有効な場合に1を引くのは、表示する目標の計算規則に限ります。練習では引き続き1～4の台詞を含む場面全体を除外するため、実際の正式クリップ数は表示された目標より少なくなる場合があります。練習を無効にすると、自動設定された目標で選択したラウンドの11場面すべてを実施できます。

ラウンドへの分割は一回の実験を短くするためのもので、カメラの画面が黒くなる問題の修正を意味しません。ラウンド間ではカメラを停止して再起動し、有効なプレビューを確認してから次のラウンドを開始することを推奨します。

同じ実験で両言語のセットを同時に選択しないでください。実験全体で使用できる言語・音声設定は一つだけです。

## Google Cloud TTS APIの設定

アプリはGoogle Cloud Text-to-SpeechのPythonクライアントでLINEAR16 WAVを生成します。音声は実験開始前に生成され、収集中はローカルキャッシュだけを再生します。

1. Google Cloudプロジェクトを作成または選択し、請求先アカウントを関連付け、Cloud Text-to-Speech APIを有効にします。Googleの[セットアップガイド](https://docs.cloud.google.com/text-to-speech/docs/get-started)を参照してください。
2. 有効にしたAPIを呼び出せるサービスアカウントを作成します。Googleの[サービスアカウント作成ガイド](https://docs.cloud.google.com/iam/docs/service-accounts-create)を参照してください。
3. サービスアカウントのJSONキーを作成し、ダウンロードします。現在のアプリはApplication Default Credentialsではなく、このJSONファイルで認証します。Googleの[サービスアカウントキーガイド](https://docs.cloud.google.com/iam/docs/keys-create-delete)を参照してください。
4. JSONはプロジェクトフォルダーと被験者データフォルダーの外に保管します。Gitへコミットしたり、収集データと一緒に共有したりしないでください。
5. アプリで **Google Cloud TTS** を有効にし、**サービスアカウントJSON** からキーを選択します。
6. 選択した問題セットに合わせて **テキスト言語コード** を設定します。
   - 中国語：`cmn-CN`
   - 日本語：`ja-JP`
7. **音声名** は空欄にするとGoogleの既定音声が使われます。言語コードに対応するGoogle Cloudの音声名を指定することもできます。必要に応じて話速を設定します。
8. 実験を開始します。不足している音声はセッション開始前に生成され、`D:\datacapture\tts_cache` に保存されます。場面の説明と各台詞には、それぞれ別のWAVファイルが作成されます。

認証情報ファイルはキャッシュや実験出力へコピーされません。音声生成に失敗した場合、再試行、音声なしで続行、実験をキャンセル、のいずれかを選択できます。
